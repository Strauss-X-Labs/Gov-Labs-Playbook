# Vibe Coding מבוסס Design System

> מקור: [5 Design Sprint_.docx](../../חומרי-מקור/מסמכים/אביבית/5%20Design%20Sprint_.docx) — תהליך 2; [GovLab_2.0_AI_Evolution.pdf](../../חומרי-מקור/מסמכים/GovLab_2.0_AI_Evolution.pdf) שקף 9.
> **סטטוס: טיוטה — טרם נבדקה ע"י אביבית.**

## מהות

המודל הישן — "אפיון ➔ סטודיו עיצוב ➔ שבועיים המתנה ➔ מפתחים ➔ שבועיים פיתוח" — הוא כשל מערכתי שמונע חדשנות. **הפרדיגמה החדשה: יום אחד, צוות אחד, מוצר עובד.**

Vibe Coding = בניית ממשק דרך שיח בשפה טבעית עם סוכן (Prompt-to-UI), כשהצוות יושב סביב המסך ומתקן בזמן אמת. מבוסס **Design System** קיים — הרכיבים כבר מעוצבים, הסדנה מרכיבה ומחברת.

**המשוואה של 2.0:** Design System קיים (Figma / Google Stitch) + Front-End שמיוצר על ידי סוכני AI = **~50% קוד מוכן.** סיום ה-Sprint אינו מסכים מצוירים — התפוקה היא מוצר אמיתי לקידוד.

## איך זה עובד

1. **Context ראשון.** קבצי ה-MD של המיזם (מפרט ה-MVP, בריף המסכים, הנחיות Design System) נטענים לסביבה. [Spec-Driven](Spec-Driven-Development.md) בפועל.
2. **Vibe Iteration.** שלד מסכים מהנחיות שפה טבעית → הצוות בודק חי → "קצר את המרחק בין הכפתור להסבר" → הסוכן משנה.
3. **Mock Data.** נתוני הדמיה מציאותיים, כדי שזו אפליקציה אינטראקטיבית — לא תמונה.
4. **Polish.** מובייל + דסקטופ, נגישות AA.
5. **Dry Run.** Golden Path על מסך גדול, בלי תקלות.

## הכלים (Tool-Agnostic)

Figma Make / Figma-to-Code · Cursor · Claude Code · v0 · Mock API Generator · Design System על Tailwind CSS / React Components. הכלי מתחלף; העיקרון לא.

## מה זה לא

- **לא עיצוב מאפס.** לוגו, גופנים, צבעים — ה-Design System כבר החליט.
- **לא קוד מוכן לייצור.** 50%, Mock Data, בלי Backend. השאר — ב-AI-SDLC אחרי יום 6.
- **לא תחליף למעצב.** איש העיצוב בחדר.
