# [שם המיזם]

repo של מיזם בתוכנית Gov-Labs. נוצר מהתבנית ב-[Gov-Labs-Playbook](https://github.com/Strauss-X-Labs/Gov-Labs-Playbook).

## איפה החומר של המיזם

הכול ב-repo הזה. זה המקום היחיד שאנשים וסוכנים בודקים.

| מה | איפה |
|---|---|
| **חומר גולמי**: מצגות, מסמכי Word, סיכומי מפגש ודיונים, ראיונות, תמונות | `01-ימים/NN-<יום>/`, תיקייה לכל יום |
| **תוצרים**: פרסונה, Lean Canvas ושאר הישויות החיות — מה שסופי, ובמיוחד מה שמוצג במליאה | `01-ימים/NN-<יום>/תוצרים/` — בתיקיית היום שבו התוצר נוצר. זה מה שהסוכנים קוראים וכותבים. ישות חיה נשארת שם ומתעדכנת שם, גם מיום אחר |
| **רפרנס למנחה**: בדיקות מוכנות, יומני סקירה, Red Team — מה שלמנטור ולארכיטקט מאחורי הקלעים, לא לצוות | `01-ימים/NN-<יום>/רפרנס-מנחה/` |
| **הפלייבוק**: המתודה והסוכנים שהמיזם עובד לפיהם | `.playbook/`, עותק של הפלייבוק. מאיזו גרסה: `.playbook/SOURCE` |

## המדריך למשתתף

מה זו התוכנית, איך עובדים עם AI, ומה קורה בכל אחד משמונת המפגשים: [מדריך-למשתתף.html](מדריך-למשתתף.html) · [הדף המפורסם](https://claude.ai/artifact/CDBAVWZZk2kdDNsAYnCA61)

## איך עובדים עם סוכן

> המדריך המלא: [המדריך למנטור לעבודה עם ה-Playbook](https://claude.ai/artifact/TDTCr53RVNnHw4VhX5XCfg).

פותחים את ה-repo הזה ב-Claude Code (או Kiro / Antigravity) **ומדברים בשפה חופשית** על מה שעושים עכשיו — למשל "אנחנו ביום 4, בוא נתחיל בבדיקת המוכנות", או "הצוות סיים את קובייה 6". הסוכן מזהה את היום ואת השלב, עובד לפי התהליך שבפלייבוק (`.playbook/01-ימים/`), קורא את החומרים מתיקיות הימים ב-`01-ימים/`, ואחרי אישור כותב את התוצר ל-`תוצרים/` של היום. אין פקודה להרצת סוכן.

אין צורך בהגדרה במחשב: מי שמוריד (clone) את ה-repo מקבל גם את הפלייבוק.

## עדכון לגרסה העדכנית של הפלייבוק

מקלידים `/update-project`. הסוכן מושך את הפלייבוק העדכני מ-GitHub ומחליף את `.playbook/`. הוא גם מעדכן את קבצי התבנית שלא נערכו ידנית, מוסיף תיקיות לימים חדשים, ומציג את התוכנית לאישור לפני שהוא משנה משהו.

את `.playbook/` לא עורכים ביד, כי הוא מוחלף כולו בכל עדכון. תיקון למתודה נכנס לפלייבוק עצמו, ב-PR.

## מה יש כאן

| תיקייה | מה |
|---|---|
| `01-ימים/` | תיקייה לכל יום בתוכנית, באותם שמות כמו `01-ימים/` בפלייבוק. בשורש התיקייה — החומר הגולמי של היום: מצגות, מסמכים, סיכומי מפגש, שיעורי בית והחלטות. בתוכה שתי תיקיות קבועות: `תוצרים/` ו-`רפרנס-מנחה/`. |
| `01-ימים/NN-<יום>/תוצרים/` | התוצרים הסופיים של היום — ובמיוחד מה שמוצג במליאה או יוצא החוצה. קובץ MD לכל תוצר, ולצידו קבצים נלווים באותו שם: תצוגה ויזואלית (`.html`) ותמונה (`.png`). קישור השיתוף בראש ה-MD. השמות זהים לשמות ב-`02-תוצרים-וטמפלטים/` בפלייבוק, וכאן ממלאים אותם בפועל. ריק בהתחלה. ישות חיה (פרסונה, Lean Canvas, דף ערכי מוצר) נשארת בתיקיית היום שבו נוצרה, ומתעדכנת שם. |
| `01-ימים/NN-<יום>/רפרנס-מנחה/` | מה שלמנטור, למנחה ולארכיטקט מאחורי הקלעים — לא לצוות ולא למליאה: בדיקות מוכנות, יומני סקירה, Red Team, יומני עבודה של כלים. ריק בהתחלה. |
| `.playbook/` | עותק של הפלייבוק, לקריאה בלבד. |
| `.kiro/steering/` | הגדרות הסוכן של המנטור. מצביע לפלייבוק, כי התהליך, הכללים והשפה מוגדרים שם ולא כאן. |
| `.mcp.json` · `.kiro/settings/mcp.json` · `.gemini/settings.json` | החיבור ל-Canva, לשיטה הדיגיטלית של ה-Lean Canvas ביום 4. מתחברים פעם אחת בכל מחשב, והסוכן מוביל את ההקמה: [`.playbook/skills/tools/canva.md`](.playbook/skills/tools/canva.md). |
