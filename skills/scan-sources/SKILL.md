# סריקת חומרי מקור

אתה עוזר לצוות Gov-Labs להפוך חומר גולמי (מצגות, תמלולים, מסמכים) לתוכן בפלייבוק — בלי לפספס כלום ובלי לקרוא הכול מחדש כל פעם.

**גבול:** אתה מעדכן את `חומרי-מקור/סטטוס.md` ומציג המלצות. אתה **לא** עורך קבצים בפלייבוק בעצמך. השילוב בפועל נעשה אחרי שבן אדם אישר.

## שלב 1 — זיהוי (סקריפט, לא שיקול דעת)

```bash
python3 skills/scan-sources/scan.py
```

הסקריפט:
- סורק את `חומרי-מקור/` רקורסיבית, משווה hash מול `סטטוס.md`
- מסמן `חדש` / `השתנה` / `נמחק`, ומוסיף שורות לטבלה
- ממיר PPTX / DOCX / XLSX / HTML / DOC / RTF לטקסט ב-`חומרי-מקור/_טקסט/<אותו נתיב>.md`
- PDF: דרך `pymupdf`. אם הפלט אומר `אין pymupdf` — הרץ פעם אחת `pip install -r skills/scan-sources/requirements.txt` והרץ שוב
- PDF סרוק (בלי שכבת טקסט) או תמונה: הסקריפט מסמן `צפה בקובץ ישירות` — פתח את הקובץ עצמו אם אתה יודע לקרוא PDF/תמונות (Claude Code יודע). אם לא — כתוב `לא נקרא` בהערות

אם הפלט אומר `ללא שינוי` בלבד ואין `ממתינים לבחינה` — דווח "אין חומר חדש" וסיים.

## שלב 2 — בחינה (שיקול דעת, אתה)

לכל קובץ בסטטוס `חדש` או `השתנה`:

1. **קרא אותו** — את הטקסט המומר ב-`_טקסט/`, או את המקור ישירות אם אין המרה.
2. **הבן מה זה** במשפט: מצגת של יום? תמלול פגישת צוות? מסמך מתודולוגי? חומר מ-Gov-Labs 1?
3. **מפה לפלייבוק.** לאיזה חלק זה נוגע — היה ספציפי, עד רמת הקובץ:
   - `00-התוכנית/…` — חזון, המסע, תפקידים, גישת AI, מילון
   - `01-ימים/NN-…` — איזה יום
   - `02-תוצרים/…` — איזה תוצר
   - `03-ידע/…` — מתודולוגיה או סטנדרט
   - `04-AI/…` — פרומפט או גייט
4. **בדוק סתירות.** פתח את הקבצים שמיפית אליהם. האם החומר החדש **סותר** משהו שכבר כתוב שם? (למשל: בפלייבוק כתוב שהפרסונה נוצרת ביום 1, במצגת היא ביום 2.) סתירה היא הממצא הכי חשוב — סמן אותה בבירור.
5. **המלץ** אחת מ:
   - `לשלב` — יש כאן תוכן שחסר בפלייבוק. ציין מה ולאן.
   - `לעדכן קיים` — יש כאן גרסה עדכנית/סותרת של משהו שכבר כתוב. ציין מה השתנה.
   - `לא רלוונטי` — לא נוגע לפלייבוק (חומר של מיזם ספציפי, שיחת חולין, כפילות של מקור אחר).
   - `חלקי` — רוב הקובץ לא רלוונטי אבל יש בו X. ציין את X.

**לתמלולי פגישות:** מה שמעניין הוא **החלטות**, לא הדיון. חלץ את ההחלטות (מה הוחלט, מי אמר, מה נדחה) ואת הפעולות. אם התמלול חסר את הכותרת המוסכמת (משתתפים / החלטות / לאן זה הלך) — הצע אותה כחלק מההמלצה.

**למצגות:** לרוב מצגת של יום מכילה גם את *מטרת היום*, גם את *התוצרים*, וגם *תוכן מתודולוגי*. פצל את ההמלצה בהתאם — כל חלק לקובץ אחר בפלייבוק.

## שלב 3 — עדכון סטטוס.md

ערוך את השורה של הקובץ ב-`חומרי-מקור/סטטוס.md`:

| עמודה | מה לכתוב |
|---|---|
| `סטטוס` | `נבחן` |
| `נוגע ל-` | נתיבי הקבצים בפלייבוק, מופרדים בפסיק. אם לא רלוונטי — `—` |
| `המלצה / הערות` | `לשלב:` / `לעדכן קיים:` / `לא רלוונטי:` / `חלקי:` + משפט-שניים. סתירה מתחילה ב-`⚠ סותר:` |

אל תיגע בעמודות `קובץ`, `hash`, `עודכן` — הסקריפט מנהל אותן.
כשבן אדם משלב את התוכן בפועל, הוא (או אתה, לבקשתו) משנה ל-`שולב` ומוסיף לינק לאן.

## שלב 4 — דיווח

סיים בדיווח קצר למשתמש, בעברית, במבנה הזה:

```
נסרקו N קבצים: X חדשים, Y השתנו, Z נמחקו.

⚠ סתירות (אם יש):
- <קובץ> סותר את <קובץ בפלייבוק>: <מה>

לשלב:
- <קובץ> → <לאן>: <מה>

לעדכן קיים:
- ...

לא רלוונטי: <רשימה קצרה>

לא הצלחתי לקרוא: <קבצים שההמרה נכשלה ואתה לא יודע לקרוא ישירות>
```

סתירות תמיד ראשונות. אם אין — כתוב "אין סתירות".

## מה לא לעשות

- לא להכניס לפלייבוק שמות של לקוחות או תוכניות אחרות (למשל "מטה הבינה"). הפלייבוק גנרי — כותבים "הגורם המזמין" / "הלקוח".

- לא לערוך קבצים ב-`00-`…`04-` — רק להמליץ.
- לא לערוך את המקורות עצמם ולא את `_טקסט/` (זה cache, הסקריפט מייצר אותו).
- לא לסמן `לא רלוונטי` רק כי הקובץ ארוך. אם לא קראת — כתוב `לא נקרא` בהערות.
- לא להמציא תוכן שלא בקובץ. אם משהו לא ברור — כתוב שלא ברור.
