**הנחיות לדיזיין סיסטם הממשלתי**

## (intro) (מבוא)

1. עקרונות יסוד
אחידות ושפה משותפת  שימוש ב־Design Tokens (צבעים, טיפוגרפיה, ריווחים, גדלים, Elevation).  אחידות בין כל משרדי הממשלה ליצירת חוויה אמינה ועקבית.
נגישות כבסיס, לא כתוספת
עמידה מלאה ב־WCAG 2.2 AA.
קונטרסט גבוה בטקסט ואייקונים.
ניווט מלא במקלדת.
ARIA roles לכל רכיב (הכוונה היא להשתמש ב־WAI-ARIA (Web Accessibility Initiative – Accessible Rich Internet Applications) כל רכיב בדיזיין סיסטם חייב לקבל תפקיד ברור (Role), מצב (State), ותוויות מתאימות (Labels), כדי שגם מי שלא רואה את המסך – יוכל להבין ולנווט בו בקלות.
מצב High Contrast Mode.
מודולריות וסקלאביליות  רכיבים מתאימים גם לטפסים פשוטים וגם לפלטפורמות מורכבות.
2. מבנה הדיזיין סיסטם (Atomic Design)
Tokens: צבעים, טיפוגרפיה, גריד, ריווחים, Elevation, מצב כהה/בהיר, RTL/LTR, High Contrast.
רכיבים בסיסיים (Atoms): כפתורים, קישורים, אינפוטים, אייקונים, טקסטים.
רכיבי תוכן (Molecules): כרטיסים, טבלאות, אקורדיונים, מודאלים.
תבניות (Patterns): טפסים ממשלתיים, זיהוי ואימות, דפי נחיתה/מידע, הודעות שגיאה, תורים ותשלומים.
Sandbox: Storybook/Figma – סביבת ניסוי עם תרחישי שימוש אמיתיים.
3. עקרונות אינטראקציה (States)
3.1 Hover
Action-Oriented = צבע  כפתורים, קישורים, אייקון־כפתור, טאבים פעילים, Checkbox/Radio/Toggle.
Content-Oriented = צל  כרטיסים, פאנלים, Dropdown Items, רשימות מורחבות, תמונות עם לינק.
3.2 Focus
מטרה: קריטי לנגישות, מפחית עומס קוגניטיבי, מספק משוב מיידי.
כפתורים: outline עבה.
שדות טקסט: outline עבה.
קישורים: outline עבה.
טאבים ותפריטים: Active = היכן אני, Focus = לאן אני עומד לעבור.
כרטיסים: פוקוס חיצוני על כל הקארד + פוקוס פנימי על רכיבים בתוכו.
סדר מקלדת: קארד > כפתור ראשי > כפתור משני.
פעולה ראשית = פוקוס בולט, פעולה משנית = פוקוס עדין, הקארד = outline עדין.
3.3 Disabled
ללא אינטראקטיביות (hover/focus/active).
ניגודיות מופחתת וברורה.
3.4 Error
הודעת שגיאה צמודה לשדה (לא בסוף טופס).
טקסט בהיר ופשוט.
צבע שגיאה עקבי (טוקן ייעודי).
3.5 Active
סימון ברור של רכיב בלחיצה/בחירה.
בידול ממצבי Hover ו־Focus.
שימוש זהיר למניעת בלבול ויזואלי.
4. Content Design
Plain Language + דוגמאות מיקרו־קופי.
טון שוויוני, מותאם תרבותית.
הודעות שגיאה אחידות.
אינדיקציות מקדימות ("מה צריך להכין מראש").
5. Layout & Responsiveness
גריד אחיד מבוסס Tokens.
רספונסיביות מלאה (מובייל, טאבלט, דסקטופ).
דפים "קלים" לחיבור חלש (הכוונה שטעינת הדפים יהיו כמה שיותר מהירים- שלא יהיו כבדים- במיוחד בדפים פוני אזרח)
תמיכה בשמירת טיוטות מקומית. (אם משתמש התחיל תהליך ועזב- שישמור לו את החלק שכבר התחיל למלא)
6. Dark Mode & High Contrast
התאמה למצבים כהים ובהירים.
שמירה על ניגודיות מספקת.
התאמות מיוחדות ל־High Contrast Mode.
7. Governance & KPIs
Changelog: תיעוד פומבי של שינויים.
KPIs:
% רכיבים שעברו ACR.
% טפסים ב־WCAG AA.
זמן מילוי טפסים, שיעור נטישה.
שביעות רצון משתמשים.
אימוץ – שימוש בפרויקטים, זמן פיתוח שנחסך.
Roadmap ציבורי + פידבק קהילתי.
8. Best Practices
כפתורים = Hover בצבע.
קארדים/פאנלים = Hover בצל.
טפסים = ולידציה צמודה לשדה.
תהליכים = Progress Indicator.
Focus = עקבי, נגיש וברור.
Disabled = לא אינטראקטיבי, ללא אשליית פעולה.
