**תבניות עיצוב הן פתרונות לשימוש חוזר לבעיות עיצוב נפוצות המתרחשות בממשקי משתמש. הן אינן עיצובים מוגמרים, אלא תבניות או הנחיות שניתן להתאים להקשרים שונים. ניתן לראות אותן כשיטות עבודה מומלצות המסייעות ליצור חוויות אינטואיטיביות, עקביות וידידותיות למשתמש.**

## סוגי תבניות עיצוב (סוגים / וריאנטים)

1.  תבניות ניווט
פירורי לחם : מציגים למשתמשים את מיקומם בתוך היררכיה.
תפריט המבורגר : מסתירים אפשרויות ניווט מאחורי סמל.
כרטיסיות : ארגן תוכן בתצוגות נפרדות.
2.  תבניות קלט וטפסים
אימות מוטמע : מספקים משוב כאשר משתמשים ממלאים טפסים.
גילוי הדרגתי : חשיפה של מידע או אפשרויות לפי הצורך.
השלמה אוטומטית : מציעים אפשרויות כאשר משתמשים מקלידים.
3.  תבניות משוב
התראות טוסט : הודעות קצרות המופיעות באופן זמני.
אינדיקטורים לטעינה : מציגים מידע לגבי משך התהליך.
הודעות שגיאה : מסבירות בבירור מה השתבש וכיצד לתקן זאת.
4.  תבניות תוכן
כרטיסים : מקבצים מידע קשור במיכל ויזואלי ייחודי.
מודלים : מדגישים תוכן הדורש את תשומת לב משתמש.
אקורדיון : הרחבה/כווץ מקטעים אשר עוזרים לניהול חלל.
5.  תבניות קליטה (Onboarding)
מדריכים : הדריכו משתמשים דרך תכונות מפתח.
Tooltips : ספקו עזרה הקשרית.
Checklists : עזרו למשתמשים להשלים משימות הגדרה (setup).

## מתי להשתמש (מתי להשתמש)

- כאשר יש צורך שחוזר על עצמו אצל המשתמשים-
- לדוגמה: שימוש ב־הודעת טוסט (Toast Notification) כדי לאשר פעולה שהצליחה מבלי להפריע לזרימת המשתמש.
- כאשר התבנית מוכרת למשתמשים ומפחיתה את העומס הקוגניטיבי -
- לדוגמה: שימוש ב־פירורי לחם (Breadcrumbs) בניווט היררכי כדי להבהיר למשתמש איפה הוא נמצא.
- יש צורך בחוויה עקבית בין מסכים, פלטפורמות או מוצרים -
- לדוגמה: שימוש ב־כרטיסים (Cards) להצגת מידע בצורה אחידה בלוח בקרה.
- כאשר יש צורך בייעל העבודה - פתרון מוכח שניתן ליישם במהירות -
- לדוגמה: שימוש ב־מודאל (Modal) למשימות קצרות כמו התחברות או אישור פעולה.
- התבניות תומכות בנגישות - התבנית כוללת שיקולי נגישות כמו ניווט מקלדת ותיאורים קוליים -
- לדוגמה: שימוש ב־ולידציה תוך כדי הקלדה בטפסים כדי להנחות את המשתמש בצורה ברורה.

## מתי להימנע (מתי להימנע)

- כאשר הן לא מתאימות להקשר -  התבנית פותרת בעיה אחרת מזו שאתה מתמודד איתה. דוגמה: שימוש ב־קרוסלה להצגת מידע חשוב-המשתמשים עלולים לפספס אותו.
- כאשר הן מקטינות את הגילוי - התבנית מסתירה תוכן או פונקציות חשובות. דוגמה: שימוש ב־תפריט המבורגר לניווט ראשי בדסקטופ.
- כאשר הן מוסיפות מורכבות מיותרת - התבנית יוצרת יותר שלבים או בלבול. דוגמה: שימוש ב־אקורדיון לתוכן קצר שיכול להיות מוצג במלואו.
- כאשר הן בשימוש יתר או בשימוש לא נכון - התבנית מיושמת בכל מקום בלי להתחשב בצרכי המשתמש. דוגמה: שימוש ב־מודאלים לכל פעולה, מה שגורם לעייפות משתמשים.
- כאשר הן סותרות את הציפיות של המשתמש -  ההתנהגות של התבנית שונה ממה שהמשתמש מצפה. דוגמה: טול־טיפ שמופיע בלחיצה במקום בריחוף- עלול לבלבל.

## כיצד נתאים לכלל האוכלוסיה (התאמה לכלל האוכלוסייה)

- במקומות שניתן, יש להוסיף איקון ליד הטקסט ולא להסתמך על איקון בלבד.
- יש להשתמש בשפה מדוברת, ישירה ובלתי-פורמלית ככל הניתן, תוך הימנעות ממונחים מקצועיים או טכנולוגיים. לדוגמה: "שלחו לנו בקשה" במקום "הגישו טופס מקוון".
- יש להימנע מהנחות על הבנת מושגים טכנולוגיים. לדוגמא: אל תשתמשו במונחים כמו "OTP", "CAPTCHA" או "upload" מבלי הסבר בעברית נגישה.
- שונות תרבותית - יש להימנע מהומור, רמיזות תרבותיות או צבעים העלולים להתפרש באופן שונה בקרב אוכלוסיות מגוונות.
- יש להתאים את הממשק לאוכלוסיה מבוגרת באמצעות טקסטים גדולים, לחצנים בולטים ופעולות איטיות (דוגמאות להאטה מכוונת בממשק: LOADER, הודעת SMS עם OTP שלא תעלם מידי מהר מהמסך, שהייה מספקת של הודעות שנעלמות אוטומטית בממשק).
- לפרטים נוספים על הכללה דיגיטלית היכנסו לקישור הבא
