# IGDS — כללי עיצוב מחייבים

מקור האמת המלא של הדיזיין סיסטם מתועד ב-#[[file:../../design.md]] והטוקנים ממומשים ב-#[[file:../../styles.css]].
כל עבודת עיצוב או פיתוח UI חייבת לעקוב אחרי הכללים הבאים ללא חריגה.

## שימוש בטוקנים (חובה)

- השתמש **תמיד** ב-CSS Custom Properties הקיימים ב-`:root` שבקובץ `styles.css`.
- **אסור** לכתוב ערכי צבע/גודל/מרווח קשיחים (hardcoded) כמו `#1a56c4`, `16px`, `24px`.
  - ✅ נכון: `color: var(--color-primary);` · `padding: var(--space-md);`
  - ❌ שגוי: `color: #1a56c4;` · `padding: 16px;`
- אם דרוש ערך שאין לו טוקן — עצור, ציין זאת, והצע להוסיף טוקן חדש ל-`:root` ול-`design.md` לפני השימוש. אל תמציא ערך אקראי.

## רכיבים

- השתמש במחלקות הקומפוננטות הקיימות: `.gov-button--primary`, `.gov-button--secondary`, `.gov-input`, `.gov-select`, `.gov-checkboxes__*`, `.gov-radios__*`, `.form-page` וכו'.
- אל תיצור רכיב חדש מאפס אם קיים רכיב מתאים. הרחב את הקיים.
- רכיב חדש חייב להשתמש רק בטוקנים ולעקוב אחרי מוסכמות השמות הקיימות (`gov-` prefix, BEM-like).

## RTL ונגישות (חובה)

- כיוון בסיס `dir="rtl"`, `lang="he"`. שמור על תמיכת RTL בכל אלמנט.
- עמידה ב-WCAG 2.1 AA לכל הפחות.
- Focus גלוי: `--focus-outline` (3px צהוב).
- שדות חובה: `aria-required`. שגיאות: `role="alert"` + `aria-invalid` + `aria-describedby`.
- Labels מפורשים לכל שדה. סדר Tab לוגי.

## עבודה מול Figma

- כשמסופק קישור ל-frame/node בפיגמה, משוך את הנתונים דרך ה-Figma MCP והשווה מול הטוקנים הקיימים.
- מפה כל ערך מפיגמה לטוקן הקרוב ביותר ב-`styles.css`. אם אין התאמה מדויקת — דווח על הפער במקום להצמיד ערך חדש בשקט.
- אל תעתיק ערכים גולמיים מפיגמה ישירות לקוד. תמיד דרך שכבת הטוקנים.
