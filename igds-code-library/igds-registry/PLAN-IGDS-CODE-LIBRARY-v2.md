## 0. שורה תחתונה

**התוצר המרכזי** הוא חבילת קוד עצמאית. השם הזמני הוא `@govlab/igds-kit`. החבילה מכילה את כל הרכיבים הרלוונטיים מ-Figma, כרכיבי Web Components עובדים, בשלוש שכבות שמופרדות זו מזו:

1. **רשמי.** `@igds/core-web` כפי שהוא, בלי שינוי, כולל הצהרת התאמה ל-Figma.
2. **קומפוזיציה.** רכיבים שבנויים רק מרכיבים רשמיים.
3. **הרחבה.** רכיבים חדשים שנוצרו מתוך מפרט Figma, בקידומת נפרדת (`igdsx-*`). הם לא מוצגים כרשמיים עד שיאושרו.

**השרשרת:**

```
Figma → מפרט מכני → יצירת קוד דטרמיניסטית → אימות → קטלוג → חבילה → כל מנוע AI
```

כל אחד מהשלבים בשרשרת אוטומטי. בני אדם מאשרים רק חריגים, ובכל שלב מקבלים רשימה מרוכזת אחת.

**Code Connect:** אופציונלי, אחרי שהספרייה קיימת. הוא לא התוצר.

## 3. חילוץ מפרט אוטומטי מ-Figma

### 3.1 ערוץ החילוץ

| ערוץ | יתרון | חיסרון | שימוש |
|---|---|---|---|
| **Figma REST API**, עם טוקן מהסביבה: `/files/:key/nodes`, `/variables/local` (Enterprise), `/images` | רץ ב-CI בלי סוכן AI. מאות צמתים בקריאה. דטרמיניסטי | דורש טוקן ואישור. [לאמת] בגישה מהרשת | **ערוץ ראשי** לחילוץ ולתחזוקה |
| **Figma MCP** (`use_figma`), קריאה בלבד | עובד היום [אומת] | מגבלת 48KB לתשובה, דורש סשן של סוכן. מתאים לפיילוט, לא ל-CI | פיילוט, וגיבוי אם הטוקן לא יאושר |

### 3.2 מה מחולץ: Component Spec, קובץ אחד לכל set

- **אנטומיה:**
  - עץ שכבות עם שמות.
  - חלקים שהם instance של רכיב אחר (תת-רכיבים, אייקונים).
  - אבני בנייה פרטיות שמשמשות את הרכיב.
- **לכל וריאנט:**
  - מאפייני הווריאנט.
  - **הפרש מוריאנט הבסיס**, ולא עותק מלא.
  - מידות.
  - sizing: ‏HUG / FILL / FIXED, ומינימום ומקסימום.
  - Auto Layout: כיוון, padding, gap, יישור, wrap.
  - constraints.
  - fills, strokes ו-radius לכל פינה.
  - effects.
  - opacity.
  - טיפוגרפיה: font, size, line-height, letter-spacing, text style.
  - קשרי משתנים (`boundVariables`).
- **Component properties:**
  - TEXT, BOOLEAN ו-INSTANCE_SWAP.
  - ערכי ברירת מחדל.
  - אילו ערכים מותרים בהחלפת instance.
- **אינטראקציות:** prototype reactions. למשל `ON_HOVER → State=Hover` או `ON_CLICK → Expanded=True`.
- **מצבי תצוגה:** ערך לכל mode (Light IGDS / Dark IGDS) דרך המשתנים.
- **קישורים:** node id, `componentKey`, גרסת הקובץ, ו-link לאימות.
- **Provenance לכל ערך:** סוג מקור אחד בלבד מתוך ארבעה:

| סוג | משמעות | דוגמה |
|---|---|---|
| `figma` | נקרא ישירות מהצומת | padding 12 קשור ל-`space-400` |
| `code` | נקרא מהחבילה הרשמית | ערך enum של attribute, טוקן CSS |
| `inferred` | נגזר בכלל מתועד (rule id), בביטחון | HUG ← `width: fit-content`; ‏`State=Hover` ← `:hover` |
| `missing` | לא קיים ולא נגזר. **דורש החלטה** | התנהגות מקלדת של רכיב חדש שלא תועדה |

### 3.3 תנאי שלמות לחילוץ

- מספר ה-sets והווריאנטים במפרט **שווה** למלאי Figma: 199 ו-2,876 ב-web, ובמובייל לפי החלטה.
- 0 וריאנטים בלי מפרט.
- כל ערך עם provenance.
- כל משתנה שקשור לצומת ממופה לטוקן CSS, או מסומן "אין טוקן".

## 4. שימוש חוזר ברכיבים הרשמיים

### 4.1 שכבת "רשמי"

- `@igds/core-web` הוא **peerDependency**. החבילה שלנו לא מעתיקה ולא משנה את קוד ה-IGDS.
- לכל תג רשמי נוצרים:
  - **חוזה:** וריאנט Figma ← attribute, property, slot או מצב runtime.
  - **הצהרת התאמה:** תוצאות האימות (§6) לכל וריאנט.

### 4.2 סיווג אוטומטי של כל set רשמי

| סטטוס | תנאי |
|---|---|
| `official-exact` | כל הווריאנטים ממופים, ועוברים בדיקת מפרט וחזותית בטווח הסבולת |
| `official-with-gaps` | חלק מהווריאנטים או המצבים חסרים בקוד, או שונים |
| `official-data-driven` | הווריאנטים מייצגים נתונים, ולא attributes. למשל `Expanded` או `Second Level` במסנן האנכי. המיפוי עובר דרך fixtures של נתונים שנגזרים מטיפוסי TS |

### 4.3 סולם פתרונות לפערים ברכיב רשמי (בלי לשנות את החבילה)

הסולם נבדק בסדר הזה. בוחרים את המדרגה הראשונה שעובדת.

1. **API רשמי קיים:** attribute, property או slot שלא זוהה במיפוי האוטומטי.
2. **Hooks רשמיים:** CSS custom properties ש-IGDS עצמו קורא ברכיב. רשימת `componentCssHooks` כבר מחולצת.
3. **עטיפה (wrapper):** `igdsx-*` שמכיל את הרכיב הרשמי ומוסיף את הווריאנט רק דרך API ציבורי.
4. **מימוש מחליף:** רכיב `igdsx-*` מלא, שמסומן `replaces: igds-x (gap: ...)`. **רק באישור.**
5. **בקשה ל-upstream:** תמיד נשלחת במקביל, עם הראיות מהאימות.

**אסור בכל המדרגות:**
- monkey-patch.
- גישה ל-shadow DOM פנימי.
- `::part` שמשנה מראה.
- העתקה של קוד רשמי.

## 5. רכיבים שאין להם מימוש רשמי

### 5.1 סיווג אוטומטי לדרגות

הסיווג מתבסס על מבנה ה-instances במפרט. הסוקר מאשר רק את הרשימה המרוכזת.

| דרגה | תנאי | דוגמאות (מועמדים, ייקבעו בסיווג) | איך מממשים |
|---|---|---|---|
| **A — וריאנט של רשמי** | המפרט תואם לתג קיים עם ערך מסוים | Text Area ← `igds-input type="textarea"`, Loaders | מיפוי בלבד |
| **B — קומפוזיציה** | בנוי בעיקר מ-instances של רכיבים שיש להם קוד | Split Button (button + popup-menu), Kpi Cards (card), Share via social links, Item Edit Modal | רכיב `igdsx-*` שמרכיב תגים רשמיים |
| **C — חדש, תצוגתי** | בלי אינטראקציה מורכבת | Stamped, Message, Updates, Small Cell Item, Dots | מחולל קוד מלא (§5.2) |
| **D — חדש, אינטראקטיבי** | קלט, מקלדת, popup, ניהול מצב | Date Range, Time Picker, Phone Number Input + Country Code, Signature, Composer AI / Prompt, Walkthrough, Mega Menu, Chat Input | מחולל לשכבה החזותית, ופיתוח התנהגות מבוקר |

### 5.2 המחולל (דטרמיניסטי, ללא LLM)

מהמפרט נוצרים:

**שלד רכיב Lit 3**, כמו הספרייה הרשמית, כדי שיהיה עקבי וניתן להחלפה בעתיד:
- **Attributes:** ממאפייני הווריאנט. השמות לפי מוסכמת שמות של IGDS, שנגזרת מהתגים הקיימים (`variant`, `size`, `disabled`…).
- **Slots ו-attributes:** מ-TEXT, BOOLEAN ו-INSTANCE_SWAP.

**Template:** מעץ האנטומיה. תת-רכיב שיש לו קוד הופך לתג הרשמי.

**CSS לפי כללים מתועדים:**

| Figma | CSS |
|---|---|
| Auto Layout | flex, padding, gap, יישור |
| HUG / FILL / FIXED | `fit-content` / `flex: 1` / px |
| משתנה קשור | `var(--igds-…)` מדויק |
| הפרש וריאנט | `:host([size="large"])` |
| `State=Hover / Focused / Pressed / Disabled` | `:hover` / `:focus-visible` / `:active` / `[disabled]` |

**Dark mode:** דרך הטוקנים הסמנטיים, שמתחלפים אוטומטית.

**בדיקות שנוצרות אוטומטית:**
- בדיקת מפרט לכל וריאנט.
- story לכל וריאנט ומצב.

### 5.3 התנהגות, שלא נמצאת ב-Figma, לפי סדר מקורות

1. **הנחיות השימוש שחולצו:** "התנהגות", "מצבים", "דגשים". → `figma`
2. **prototype reactions.** → `figma`
3. **רכיב רשמי עם אותו דפוס:** שימוש חוזר, למשל `igds-popup-menu` לתפריט. → `code`
4. **דפוס WAI-ARIA APG המתאים:** מקלדת ו-ARIA. → `inferred-standard`. דורש אישור נגישות.
5. **כל השאר:** `missing`. ההחלטה נרשמת ברשימה המרוכזת.

**ההתנהגות של דרגה D נכתבת על ידי מפתח, או AI בפיקוח מפתח, ועוברת סקירה.** המחולל לא ממציא התנהגות.

- `dir="rtl"` לווריאנטי `RTL=True`.
- mode בהיר או כהה לפי `data-theme`.

### 6.2 שלוש רמות בדיקה חזותית

| רמה | מה נבדק | למה |
|---|---|---|
| **1. מפרט (ראשית)** | computed style ו-bounding box של הרכיב וחלקיו, מול ערכי המפרט: מידות, padding, gap, צבע, גופן, radius, צל. סבולת 0.5px וצבע מדויק | הוכחה מספרית, בלי תלות ברינדור גופנים |
| **2. פיקסלים** | השוואה תפיסתית מול PNG מ-Figma, עם תמונת diff | תופסת מה שהמפרט לא מכסה: אייקון שגוי, סדר, חיתוך |
| **3. מבנה** | התאמה בין טקסטים, אייקונים וסדר החלקים לעץ האנטומיה | מוודאת שלא חסר או נוסף חלק |

**מצבים:**
- hover, focus ו-active מאולצים דרך `CSS.forcePseudoState` של CDP.
- disabled, error ו-selected דרך attributes או נתונים.

**רספונסיביות:** רינדור בנקודות השבירה שבעמוד הגריד ב-Figma: ‏360, 784, 1440 ו-1920, ובוריאנטי Desktop/Mobile הקיימים.

**ברכיב רשמי, פער הוא ממצא upstream.** הוא נרשם בהצהרת ההתאמה ולא "מתוקן".

### 6.3 בדיקות התנהגות

הבדיקות נוצרות מהחוזה, לפי סוג הרכיב:
- לחיצה ואירועים: רק אירועים מהקטלוג.
- פתיחה וסגירה, ו-Escape.
- בחירה והקלדה.
- מצבי שגיאה: `invalid`, `error`.
- ניווט מקלדת: Tab, חיצים, Enter ו-Space לפי APG.
- focus גלוי ומלכודת focus בחלונות.
- RTL: כיוון חיצים.
- axe-core: 0 הפרות WCAG 2.2 AA.
- התנהגות בכל נקודות השבירה.

**לכל בדיקה יש תווית מקור:**
- `documented`: ב-Figma או בתיעוד הרשמי.
- `required-for-working-component`: נדרש כדי שהרכיב יעבוד, אבל לא תועד.

### 6.4 בדיקת שלמות וכיסוי (רשימת אב)

**כל set רלוונטי ב-Figma** נכנס לרשימת האב, עם סטטוס אחד:

| סטטוס | משמעות |
|---|---|
| `official` | מימוש רשמי, אומת |
| `generated` | הרחבה שנוצרה ואומתה |
| `composition` | קומפוזיציה שנוצרה ואומתה |
| `verifying` | בתהליך אימות |
| `blocked` | חסר או חסום, עם סיבה ובעלים |

**הדוח מציג את המדדים האלה:**
- sets שזוהו.
- ייחודיים, אחרי איחוד כפילויות. למשל 217 סטי האייקונים הכפולים ב-.Atoms, ו-Prompt ו-Composer AI שמופיעים פעמיים.
- כמה קיימים בקוד, כמה נוצרו וכמה אומתו.
- וריאנטים ומצבים שנבדקו, לפי רמה.
- פערים פתוחים.

**אין הצהרת "100%" בלי ראיה ממוחשבת לכל שורה.**

## 8. הפצה לכל מנוע AI ואכיפה

### 8.1 החבילה `@govlab/igds-kit` (שם זמני)

```
@govlab/igds-kit
├─ official/        מניפסט + חוזה + הצהרות התאמה (מייבא את @igds/core-web, לא מעתיק)
├─ ext/             רכיבי igdsx-* (דרגות B/C/D) + עטיפות לפערים
├─ patterns/        תבניות (טפסים, משוב…) כרכיבים
├─ templates/       תבניות עמוד מ-12 הפריסות
├─ tokens/          re-export של @igds/tokens + igdsx-tokens.css (רק טוקנים שחסרים בקוד, ערכים מ-Figma)
├─ icons/           @igds/icons + אייקונים שחסרים (SVG מ-Figma)
├─ ai/              AGENTS.md · llms.txt · catalog.json · כרטיסי הנחיות · אינדקס לפי מטרה
└─ cli/             igds-kit lint · igds-kit verify · igds-kit doctor
```

**תבנית פרויקט:** `create-govlab-app`. כוללת טעינה נכונה, lint ב-pre-commit, CI, ואת קבצי ה-AI במקום הנכון.

### 8.2 מה ה-AI מקבל

הקבצים לא תלויים במנוע. `AGENTS.md` נקרא כסטנדרט, ונוספים מתאמים של שורה אחת לכל כלי:
- רשימת רכיבים ומתי להשתמש בכל אחד.
- import.
- attributes וערכים מותרים.
- הרכבה למסך: תבניות.
- מה אסור.
- איך מדווחים על רכיב חסר.

### 8.3 אכיפה (לא הנחיה מילולית)

**`igds-kit lint`** מרחיב את `igds:lint` הקיים:
- כל הכללים הקיימים.
- `E-NATIVE-SUBSTITUTE`: תחליף מקומי כש-IGDS כולל רכיב מתאים.
- `E-STYLE-OVERRIDE`: CSS שמשנה מראה פנימי.
- `E-STATE-AS-ATTR`: כתיבת מצב runtime כ-attribute.
- `E-REDEFINE`: הגדרה מחדש של `igds-*` או `igdsx-*`.
- `E-COPY`: העתקת קוד רכיב לפרויקט.

**`igds-kit doctor`:** בודק hash של החבילות ב-`node_modules` מול הגרסה שפורסמה. שינוי מקומי ברכיב מאושר מכשיל את הבדיקה.

**שער CI:** אי אפשר למזג שינוי שנכשל ב-lint.

### 8.4 Code Connect ו-MCP

| כלי | תפקיד | מתי |
|---|---|---|
| Figma MCP | חילוץ וחקירה, פיילוט | עכשיו. קריאה בלבד |
| Figma REST | חילוץ ותחזוקה ב-CI | אחרי אישור טוקן |
| Code Connect | מיפוי Figma ← רכיבי **הספרייה שלנו**, כדי שקישור לעיצוב יתורגם לקוד הספרייה | **אופציונלי**, אחרי שלב 6, ורק באישור. לא תחליף לספרייה |

שרת MCP חדש לא נדרש. אפשר לשקול אותו בעתיד לחיפוש בקטלוג, אבל הוא לא חלק מהתוכנית.
