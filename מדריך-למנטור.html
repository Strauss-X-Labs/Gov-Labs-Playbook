Gov-Labs 2.0 · מדריך למנטור

המדריך למנטור לעבודה עם ה-Playbook

הפלייבוק מחזיק את המתודה ואת הגדרות הסוכנים, פעם אחת לכל המיזמים. המיזם שלך מחזיק את החומרים והתוצרים של הצוות. המדריך מסביר איך מחברים ביניהם, ב-Windows או ב-Mac, ובכל כלי AI: Claude Code, Gemini, Kiro ואחרים.

איך זה בנוי

הסוכן רץ מתוך המיזם שלך. הוא קורא את המתודה מהפלייבוק ואת החומרים מתיקיית היום, מתשאל את הצוות, וכותב את התוצר למיזם רק אחרי אישור.

1הכנת סביבת העבודה

פעם אחת, לפני המיזם הראשון. אפשר לסמן כל שורה אחרי שסיימת.

רשימת התקנות

טרמינל ופקודות

את הפקודות מריצים בטרמינל. ב-VS Code וב-Kiro: בתפריט Terminal בוחרים New Terminal. ב-Windows בוחרים Git Bash בחץ הקטן ליד סימן הפלוס בחלון הטרמינל. ב-Mac הטרמינל הרגיל מתאים.

זהות git, פעם אחת (עם השם והמייל שלך):

git config --global user.name "השם שלך"
git config --global user.email "you@example.com"

העתקת הפלייבוק למחשב, פעם אחת:

mkdir -p /c/Dev
git clone https://github.com/Strauss-X-Labs/Gov-Labs-Playbook.git /c/Dev/Gov-Labs-Playbook
mkdir -p ~/Dev
git clone https://github.com/Strauss-X-Labs/Gov-Labs-Playbook.git ~/Dev/Gov-Labs-Playbook

עדכון הפלייבוק לפני כל שבוע עבודה, כדי לקבל שינויים במתודה ובסוכנים:

git -C /c/Dev/Gov-Labs-Playbook pull
git -C ~/Dev/Gov-Labs-Playbook pull

בדיקה שהכל עובד

  1. פתח את תיקיית הפלייבוק בעורך (File ואז Open Folder), ואת כלי ה-AI בתוכה.
  2. בדוק שהכלי רואה את ההוראות. ב-Claude Code וב-Gemini CLI מקלידים /, ו-onboard-project צריך להופיע ברשימה. בכלים אחרים שואלים: "מה יש בתיקייה skills?", ובתשובה צריכים להופיע onboard-project ו-run-agent.
  3. לא עובד? עדכן את הפלייבוק (git pull) ופתח את הכלי מחדש. ראה גם תקלות נפוצות.

מהלך ההקמה

  1. פותחים את תיקיית הפלייבוק ומפעילים את ההקמה. ב-Claude Code או ב-Gemini CLI מקלידים /onboard-project. בכלים אחרים מדביקים את משפט הפתיחה. הסוכן שואל את חמשת הפרטים מהטבלה.
  2. בדיקות מקדימות. הסוכן בודק זהות git, ששם ה-repo פנוי ושיש לך הרשאה לפתוח אותו, ושתיקיית ה-Drive קיימת וניתנת לכתיבה.
  3. אישור. מוצגת טבלה של כל מה שייווצר. שום דבר לא נוצר לפני שכתבת "כן".
  4. ביצוע. הסוכן עושה ארבעה דברים:
    • פותח repo פרטי ומעתיק אליו את תבנית המיזם.
    • יוצר תיקייה לכל יום בתוכנית, לפי הימים שבפלייבוק.
    • דוחף את הכל ל-GitHub.
    • יוצר ב-Drive תיקיית מיזם, ובתוכה תיקייה לכל יום.
  5. חיבור לפלייבוק. הסוכן מחבר את המיזם לפלייבוק ול-Drive במחשב שלך. הנתיבים נשמרים בקובץ מקומי שלא עולה ל-GitHub, כי הם שונים בכל מחשב.
  6. דיווח. תקבל לינק ל-repo ולתיקיית ה-Drive, ורשימה של מה שנשאר לך לעשות: לתת הרשאות לחברי הצוות ב-GitHub וב-Drive.

מחשב נוסף או חבר צוות

במחשב שבו הקמת את המיזם הוא כבר מחובר. אם בשורש המיזם יש קובץ בשם .gov-labs.local, לא צריך לעשות כלום.

במחשב אחר צריך את הפלייבוק (שלב 1) ועותק של ה-repo של המיזם:

git clone https://github.com/Strauss-X-Labs/gov-labs-cycle10-climate.git /c/Dev/gov-labs-cycle10-climate
git clone https://github.com/Strauss-X-Labs/gov-labs-cycle10-climate.git ~/Dev/gov-labs-cycle10-climate

הרצת סוכן

פותחים את תיקיית המיזם (לא את הפלייבוק), ומבקשים סוכן לפי שם. ב-Claude Code או ב-Gemini CLI:

/run-agent פרסונה דיגיטלית

בכל כלי אחר מדביקים את משפט הפתיחה עם שם הסוכן. בלי שם, הסוכן מציג את רשימת הסוכנים לפי ימים ושואל. הרשימה המלאה נמצאת ב-טבלת הסוכנים בפלייבוק. סוכן חדש שנוסף לפלייבוק זמין מיד, בלי התקנה.

מה קורה בהרצה:

  1. קריאת המתודה. הסוכן קורא מהפלייבוק את מפרט הסוכן, התהליך, המתודה והטמפלט של התוצר.
  2. קריאת המיזם. הוא קורא את התוצרים הקיימים ואת תיקיית היום, מציג את רשימת הקבצים ב-Drive, ושואל אילו רלוונטיים. הוא קורא מצגות, Word, PDF ותמונות.
  3. בדיקת קלטים. מוצגת טבלה של מה יש ומה חסר מתוך מה שהמפרט דורש. מה שחסר נשאל מהצוות, ולא מומצא.
  4. תשאול הצוות. שאלה אחת בכל פעם, לפי התסריט שבמפרט. הסוכן מאתגר, שואל "למה?", ושם לב לנורות האזהרה של התהליך.
  5. טיוטה. הסוכן מציג טיוטה במבנה של הטמפלט, כשהשערות מסומנות כהשערות. הצוות מתקן.
  6. כתיבה. רק אחרי אישור הצוות התוצר נכתב ל-תוצרים/. אם התוצר כבר קיים, הסוכן מציג מה משתנה ומעדכן, בלי לדרוס.
  7. תצוגה ותמונה, כשהסוכן מגדיר אותן. לדוגמה, בפרסונה נשמרים ליד קובץ ה-MD, באותו שם, גם תצוגה ויזואלית (.html) ותמונה. אם הכלי לא מחולל תמונות, הסוכן כותב פרומפט לכלי חיצוני, ואתה שומר את התמונה בשם שהוא נותן. אם הכלי מפרסם דפים לשיתוף, קישור השיתוף נרשם בראש קובץ ה-MD, ובכל עדכון הדף מתפרסם מחדש לאותו קישור.
  8. סיכום. מה נכתב, על מה זה מבוסס, ומה כדאי לבדוק בשטח. הסוכן גם מציע את הצעד הבא בתהליך.
מה הסוכן לא עושה

לא עורך את הפלייבוק, לא כותב ל-Drive, לא ממציא מידע חסר, לא מחליט במקום הצוות, ולא שומר ב-GitHub בלי אישור.

תתי-צוותים במקביל

בתהליכים כמו הפרסונה, שני תתי-צוותים עובדים בו-זמנית. כל תת-צוות צריך סשן משלו: שני חלונות של כלי ה-AI על אותו מיזם, או שני מחשבים מחוברים (ראה מחשב נוסף).

שמירה ושיתוף

בסוף ההרצה הסוכן מציע לשמור (commit). אפשר לאשר לו, או להריץ בעצמך בטרמינל, מתוך תיקיית המיזם:

git add תוצרים/ ימים/
git commit -m "כרטיס פרסונה: מירב (תת-צוות 1)"
git push

git push מעלה ל-GitHub, ורק אז שאר הצוות רואה את התוצרים. מי שעובד ממחשב נוסף מושך את העדכונים עם git pull.
