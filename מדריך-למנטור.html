Gov-Labs 2.0 · מדריך למנטור

המדריך למנטור לעבודה עם ה-Playbook

הפלייבוק מחזיק את המתודה ואת הגדרות הסוכנים, פעם אחת לכל המיזמים. המיזם שלך מחזיק את החומרים והתוצרים של הצוות. המדריך מסביר איך מחברים ביניהם: מהכנת המחשב, דרך הקמת המיזם, ועד הרצת סוכנים עם הצוות.

1הכנת סביבת העבודהפעם אחת, כשעה 2הקמת מיזםפעם אחת לכל מיזם, כ-5 דקות 3עבודה שוטפתבכל מפגש עם הצוות

איך זה בנוי

הסוכן רץ מתוך המיזם שלך. הוא קורא את המתודה מהפלייבוק ואת החומרים מתיקיית היום, מתשאל את הצוות, וכותב את התוצר למיזם רק אחרי אישור.

קוראים בלבד

הפלייבוק

מפרט הסוכן, התהליך של היום, המתודה והטמפלט של התוצר. זהה לכל המיזמים.

Google Drive

הצוות לא צריך לדעת git. הצוות עובד ב-Drive כרגיל, ואת הסוכן מפעילים המנטור או מפעיל ה-AI של הצוות.

1הכנת סביבת העבודה

פעם אחת, לפני המיזם הראשון. אפשר לסמן כל שורה אחרי שסיימת.

רשימת התקנות

זהות git, פעם אחת (עם השם והמייל שלך):

git config --global user.name "השם שלך"
git config --global user.email "you@example.com"

העתקת הפלייבוק למחשב, פעם אחת:

mkdir -p /c/Dev
git clone https://github.com/Strauss-X-Labs/Gov-Labs-Playbook.git /c/Dev/Gov-Labs-Playbook

עדכון הפלייבוק לפני כל שבוע עבודה, כדי לקבל שינויים במתודה ובסוכנים:

git -C /c/Dev/Gov-Labs-Playbook pull

בדיקה שהכל עובד

  1. פתח את תיקיית הפלייבוק ב-Claude Code. ב-VS Code: File ואז Open Folder, ובחר C:\Dev\Gov-Labs-Playbook. מהטרמינל: cd /c/Dev/Gov-Labs-Playbook ואז claude.
  2. הקלד / בשורת ההודעה. ברשימה צריכים להופיע onboard-project ו-scan-sources.
  3. לא מופיעים? עדכן את הפלייבוק (git pull) ופתח את Claude Code מחדש. ראה גם תקלות נפוצות.

מהלך ההקמה

  1. פתח את הפלייבוק ב-Claude Code והקלד /onboard-project. הסקיל שואל את חמשת הפרטים מהטבלה.
  2. בדיקות מקדימות. הסקיל בודק זהות git, ששם ה-repo פנוי ושיש לך הרשאה לפתוח אותו, ושתיקיית ה-Drive קיימת וניתנת לכתיבה.
  3. אישור. מוצגת טבלה של כל מה שייווצר. שום דבר לא נוצר לפני שכתבת "כן".
  4. ביצוע. הסקיל עושה ארבעה דברים:
    • פותח repo פרטי ומעתיק אליו את תבנית המיזם.
    • יוצר תיקייה לכל יום בתוכנית, לפי הימים שבפלייבוק.
    • דוחף את הכל ל-GitHub.
    • יוצר ב-Drive תיקיית מיזם, ובתוכה תיקייה לכל יום.
  5. חיבור לפלייבוק. הסקיל מחבר את המיזם לפלייבוק ול-Drive במחשב שלך. הנתיבים נשמרים בקובץ מקומי שלא עולה ל-GitHub, כי הם שונים בכל מחשב.
  6. דיווח. תקבל לינק ל-repo ולתיקיית ה-Drive, ורשימה של מה שנשאר לך לעשות: לתת הרשאות לחברי הצוות ב-GitHub וב-Drive.

חבר צוות שמצטרף, או מחשב נוסף

במחשב שבו הקמת את המיזם הוא כבר מחובר. אם בשורש המיזם יש קובץ בשם .gov-labs.local, לא צריך לעשות כלום.

מי שעובד על המיזם ממחשב אחר צריך את הפלייבוק במחשב (שלב 1) ועותק של ה-repo של המיזם:

git clone https://github.com/Strauss-X-Labs/gov-labs-cycle10-climate.git /c/Dev/gov-labs-cycle10-climate
  1. פותחים את תיקיית המיזם ב-VS Code ואת Claude Code בתוכה.
  2. מקלידים /run-agent. הסוכן מזהה שהמחשב לא מחובר, שואל איפה הפלייבוק ואיפה תיקיית המיזם ב-Drive, ומחבר לבד. זה קורה פעם אחת בלבד.

חיבור ידני, אם צריך: ב-VS Code בוחרים Terminal ואז New Terminal. בחץ הקטן ליד סימן הפלוס בוחרים Git Bash, ומריצים את הפקודות הבאות. הפרמטר האחרון הוא תיקיית המיזם ב-Drive, ומדלגים עליו אם החומר נשמר ב-ידע/.

cd /c/Dev/Gov-Labs-Playbook
bash skills/run-agent/connect.sh "/c/Dev/gov-labs-cycle10-climate" "G:\...\Gov Labs - מחזור 10 - אקלים"

הרצת סוכן

פותחים ב-Claude Code את תיקיית המיזם (לא את הפלייבוק), ומקלידים /run-agent עם שם הסוכן. למשל:

/run-agent פרסונה דיגיטלית

בלי שם, הסוכן מציג את רשימת הסוכנים לפי ימים ושואל. הרשימה המלאה נמצאת ב-טבלת הסוכנים בפלייבוק. סוכן חדש שנוסף לפלייבוק זמין מיד, בלי התקנה.

מה קורה בהרצה:

  1. קריאת המתודה. הסוכן קורא מהפלייבוק את מפרט הסוכן, התהליך, המתודה והטמפלט של התוצר.
  2. קריאת המיזם. הוא קורא את התוצרים הקיימים ואת תיקיית היום, מציג את רשימת הקבצים ב-Drive, ושואל אילו רלוונטיים. הוא קורא מצגות, Word, PDF ותמונות.
  3. בדיקת קלטים. מוצגת טבלה של מה יש ומה חסר מתוך מה שהמפרט דורש. מה שחסר נשאל מהצוות, ולא מומצא.
  4. תשאול הצוות. שאלה אחת בכל פעם, לפי התסריט שבמפרט. הסוכן מאתגר, שואל "למה?", ושם לב לנורות האזהרה של התהליך.
  5. טיוטה. הסוכן מציג טיוטה במבנה של הטמפלט, כשהשערות מסומנות כהשערות. הצוות מתקן.
  6. כתיבה. רק אחרי אישור הצוות התוצר נכתב ל-תוצרים/. אם התוצר כבר קיים, הסוכן מציג מה משתנה ומעדכן, בלי לדרוס.
  7. סיכום. מה נכתב, על מה זה מבוסס, ומה כדאי לבדוק בשטח. הסוכן גם מציע את הצעד הבא בתהליך.
מה הסוכן לא עושה

לא עורך את הפלייבוק, לא כותב ל-Drive, לא ממציא מידע חסר, לא מחליט במקום הצוות, ולא שומר ב-GitHub בלי אישור.

תתי-צוותים במקביל

בתהליכים כמו הפרסונה, שני תתי-צוותים עובדים בו-זמנית. כל תת-צוות צריך סשן משלו: שני חלונות Claude Code על אותו מיזם, או שני מחשבים מחוברים. ההגדרה לכל מחשב נוסף מופיעה בחבר צוות שמצטרף.

שמירה ושיתוף

בסוף ההרצה הסוכן מציע לשמור (commit). אפשר לאשר לו, או להריץ בעצמך מתוך תיקיית המיזם:

git add תוצרים/ ימים/
git commit -m "כרטיס פרסונה: מירב (תת-צוות 1)"
git push

git push מעלה ל-GitHub, ורק אז שאר הצוות רואה את התוצרים. מי שעובד ממחשב נוסף מושך את העדכונים עם git pull.
