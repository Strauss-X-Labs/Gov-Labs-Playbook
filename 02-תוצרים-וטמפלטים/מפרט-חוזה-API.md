## מה זה ולמה

החוזה של כל ממשק — נסגר, נבדק ומקבל כתובת רצה **לפני** שנכתבת שורת לוגיקה עסקית. כך שני צדדים בונים במקביל מול אותו חוזה, והארכיטקט מוודא שכל מי שמעורב מתיישר לארכיטקטורה.

**ארבעה פלטים, כולם נגזרים מהמפרט:** מפרט OpenAPI · מוק רץ · בדיקות חוזה · אוסף Postman. שום דבר לא נכתב ביד בנפרד, כדי שלא ייווצר פער ביניהם.

## המבנה

```markdown
# מפרט חוזה API — [שם המיזם]
> גרסה: v0.1 · ארכיטקטורה: [לינק, סעיף 4] · עודכן: [תאריך]

## 1. רשימת הממשקים
| ממשק | בין מי למי | סיפורים | בעלים | סטטוס |
|---|---|---|---|---|
| [שם] | [צרכן] → [ספק] | US-__ | | מפרט / מוק רץ / בדיקות עוברות |

## 2. לכל ממשק: [שם הממשק]
- **מפרט OpenAPI:** `מפרט-חוזה-API.<שם-הממשק>.openapi.yaml`
- **נתיבים:** 
| פועל | נתיב | מה עושה | סיפור |
|---|---|---|---|

- **מקרי שגיאה:**
| מקרה | קוד | מבנה תשובה |
|---|---|---|
| אין הרשאה | 401 / 403 | |
| המשאב לא קיים | 404 | |
| קלט לא תקין | 400 / 422 | |
| המערכת בצד השני לא זמינה | 503 | |

## 3. מוק
כתובת: [URL שאפשר לקרוא לו מחוץ לסביבת המפתח] · מה מחזיר: דוגמאות תקינות לכל נתיב, כולל מקרי השגיאה.

## 4. בדיקות חוזה ואוסף Postman
- אוסף: `מפרט-חוזה-API.<שם-הממשק>.postman.json`
- איך מריצים: [הפקודה]
- רצות מול: המוק עכשיו, והמימוש האמיתי בפיילוט
```

### הערות

- **שדה בלי מקור** בסיפור או בארכיטקטורה — "חסר מידע", לא ממציאים.
- **בלי כתובת מוק שאפשר לקרוא לה — החוזה לא נסגר.**
- **המוק לא מממש לוגיקה עסקית.** הוא מחזיר דוגמאות.

> ⚠ ממתין להחלטה: קבצי ה-OpenAPI וה-Postman נשמרים ליד ה-MD, באותו שם בסיס. [הכלל לקבצים נלווים](README.md) מתיר היום HTML ותמונה בלבד.

## איך זה ממשיך לחיות

בפיילוט, לפני שהספק כותב לוגיקה: מממש את החוזה, ובדיקות החוזה עוברות מול המימוש. שינוי בממשק — משנים את המפרט, ומשם גוזרים מחדש את המוק, הבדיקות והאוסף.
