4. מבנה מטריצת תרגום ערכים לרכיבים (Value-to-Component Matrix)
ערך מוצר מכונן
התנהגות הממשק הנגזרת (UX Principle)

מיקרו-קופי לדוגמה
1. בהירות ורוגע (Radical Clarity)
ביטול מוחלט של מושגים משפטיים וזמני המתנה מעורפלים.
Smart Status Timeline — ציר ויזואלי ברור עם צפי טיפול מדויק.
"המסמך נקלט בהצלחה. סוכן הזכאות בודק אותו כעת, נחזור אליך בתוך שעתיים."
2. אפס בירוקרטיה (Zero Friction)
המשתמש אינו מזין מידע שכבר קיים במערכות המדינה.
Instant Document Ingestion & Pill Display — גרירת קובץ בודד וחילוץ נתונים מיידי.
"זיהינו את כל הנתונים הדרושים. לחץ כאן רק כדי לאשר."
3. שקיפות ושליטה (Human Agency)
הסבר פשוט לכל מסקנה שהופקה על ידי מודל ה-AI.
Why & How Tooltip + Override Toggle — יכולת לראות את מקור המידע ולתקנו בלחיצה.
"מדוע זכאי למענק? על פי סעיף 4א' להסכם משרד העבודה מ-2023 [הצג מקור]".
5. נורות אזהרה למנטור (Red Flags)
🚩 ערכים שנשארים סיסמאות באוויר: הצוות קובע ערך של "חדשנות ואמון", אך בפועל בונה טופס ארוך עם 30 שדות חובה באותיות קטנות. התערבות מנטור: "איפה רואים את האמון במסך הזה? אם יש אמון — למה אנחנו מבקשים מהאזרח לחתום על 3 הצהרות שונות?"
תהליך: ייצור 50% מהפרונט והקוד בגישת AI SDLC ו-Vibe Coding (vibe-coding-and-figma-make.md)
1. מטרה
בעידן של AI SDLC ו-Vibe Coding, המודל הישן של "אפיון ➔ העברה לסטודיו עיצוב ➔ שבועיים המתנה ➔ העברה למפתחים ➔ שבועיים פיתוח" הוא כשל מערכתי שמונע חדשנות.
הפרדיגמה החדשה: יום אחד, צוות אחד, מוצר עובד. באמצעות שילוב כלי יצירה מודרניים (Figma Make, Cursor, Claude Code, v0), הצוות יחד עם ה-End-to-End Product Lead מייצרים בתוך 4 שעות עבודה מעבדתית 50% מקוד הפרונטנד של המוצר, כשהוא מחובר למערכת עיצוב (Design System) אמיתית, רספונסיבי, ופועל עם Mock Data אינטראקטיבי.
2. מפרט סביבת הפיתוח והכלים (Tools & Agent Setup)
Design System Repository: ספריית רכיבים ממשלתית מודרנית מבוססת Tailwind CSS / React Components.
כלי Vibe Coding מרכזיים:
Figma Make / Figma-to-Code: תרגום מיידי של ארכיטקטורת המסכים לרכיבי קוד תוכנה.
Cursor / Claude Code / v0: סביבות פיתוח מונחות סוכנים המייצרות קבצי קוד שלמים (Components, Layouts, Routing) מתוך מפרטי ה-MD.
Mock API Generator: סוכן המייצר קבצי JSON מדומים ומדויקים המדמים את תגובות מערכות הליבה ושכבות ה-AI.
3. פירוט השלבים שלב-אחר-שלב (Step-by-Step Flow)
שלב א': הזנת ה-Context וה-Design System לסביבת ה-Vibe Coding (20 דקות):
ה-Product Lead טוען לתוך סביבת העבודה (למשל סביבת Cursor / v0) את קבצי ה-MD של המיזם:
mvp-definition-spec.md (מפרט ה-Core Loop)
product-values-spec.md (מטריצת הרכיבים)
הנחיות ה-Design System הממשלתי (צבעים, טיפוגרפיה, רכיבי כפתורים ושדות).
שלב ב': ייצור מסך הכניסה ולולאת הפעולה הראשית (Vibe Iteration 1) (60 דקות):
הפקת שלד המסכים הראשון באמצעות הנחיות שפה טבעית מובנות (Prompt-to-UI).
הצוות יושב סביב המסך: מבצע בדיקה חיה, מזהה חיכוך, ומשנה את הקוד בזמן אמת באמצעות שיח מול הסוכן ("קצר את המרחק בין הכפתור להסבר, הפוך את העלאת הקובץ ל-Drag and Drop ענק, ושקף את ערך השקט הנפשי").
שלב ג': הזרקת Mock Data וחיבור שכבת ה-AI המדומה (45 דקות):
הסוכן מייצר נתוני הדמיה מציאותיים לחלוטין (תעודות זהות מדומות, קבצי PDF לדוגמה, תשובות סוכן אנליטיקה).
חיבור הנתונים לרכיבי הממשק כך שהאב-טיפוס אינו סתם "תמונה סטטית", אלא אפליקציית Web אינטראקטיבית מלאה שניתן להקליד בה ולקבל תגובות מיידיות.
שלב ד': סבב ליטוש חווייתי (Design Polish & Polish Loop) (40 דקות):
התאמה לרזולוציית מובייל ודסקטופ.
וידוא עמידה בעקרונות נגישות ממשלתיים (רמת AA).
שלב ה': בדיקת מעבר חיה (Click-Through Dry Run) (15 דקות):
חבר צוות מדגים את המסלול המלא (Golden Path) על גבי המסך הגדול ללא תקלות.
