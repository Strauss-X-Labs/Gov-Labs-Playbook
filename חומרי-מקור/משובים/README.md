# משובים מהימים

הערות מהמחזורים: מה עבד ביום ומה לא, ממנטורים, מנחים ומשתתפים. זה **חומר מקור**, וממנו מעדכנים את הפלייבוק.

## המבנה

```
משובים/
  מחזור-NN/
    01-Unboxing.md
    02-Design-Thinking-1.md
    …
    08-Storytelling.md
```

- **תיקייה לכל מחזור**: `מחזור-<מספר>`. מספר המחזור בלבד, בלי שם הגורם המזמין ([כלל 8](../../איך-תורמים.md)).
- **קובץ לכל יום**, באותו שם כמו התיקייה ב-[01-ימים/](../../01-ימים/). יום שלא היה עליו משוב — אין קובץ.
- **מוסיפים, לא משכתבים.** הערה שנכתבה נשארת. תיקון או הבהרה — הערה חדשה מתחתיה.

## איך נראה קובץ יום

```markdown
# משוב — מחזור NN · 04 Lean Canvas
> תאריך המפגש: YYYY-MM-DD

- **[מנטור]** ההערה, במילים של מי שאמר אותה. · נוגע ל: תהליך 3
- **[משתתף]** … · נוגע ל: לא ידוע
```

- **מי** — תפקיד, לא שם: מנטור · מנחה · משתתף · ארכיטקט · נציג טכנולוגי · נציג מוצרי.
- **נוגע ל** — תהליך, תוצר או סוכן, אם ידוע. לא ידוע — כותבים "לא ידוע", והסריקה תמפה.
- **תמלול מלא** של שיחת משוב — ל-[תמלולי-פגישות/](../תמלולי-פגישות/), ולקשר אליו מכאן.

## מה קורה עם משוב

1. **כותבים בענף `feedback/days`.** הענף נשאר פתוח לאורך כל המחזורים.
2. **מריצים `scan-sources`.** קובץ יום חדש, או קובץ שנוספו לו הערות, מסומן ב-[סטטוס.md](../סטטוס.md) עם המלצה: לשלב, לעדכן קיים, או לא רלוונטי.
3. **מה שמוחלט לשלב נכנס לפלייבוק**, ומגיע ל-`main` ב-PR.
4. **מדי פעם מושכים את `main` לענף**, כדי שלא יתרחק.
